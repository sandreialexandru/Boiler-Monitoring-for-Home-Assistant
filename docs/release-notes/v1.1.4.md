### Fixed: "Custom element doesn't exist: boiler-monitor-card" appearing on some page loads
Root cause found on a live system: Home Assistant can replace the browser's custom-element registry with a polyfilled one (*scoped custom element registry*) a moment after the page starts. The card was loaded very early (as an extra frontend module), so on some reloads it registered itself **before** the swap and became invisible to the new registry. Whether a reload worked depended on which script won the race.

- The card now registers itself again on the new registry if it was swapped, so it is found whichever way the race goes.
- In storage-mode dashboards the card is loaded **only** as a dashboard resource, which runs after the frontend has started. The early "extra module" path is used only as a fallback for YAML-mode dashboards.

> Other custom cards shipped by integrations with `add_extra_js_url` can show the same symptom.

### Upgrade
Update via HACS and restart Home Assistant. Then once: Ctrl+F5 in the browser, and in the companion app *Settings → Companion app → Debugging → Reset frontend cache*.
