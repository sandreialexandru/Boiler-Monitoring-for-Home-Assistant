### Fixed: burner entity unavailable during a burn
- When the burner entity becomes `unavailable` / `unknown` while burning, the cycle is closed at that moment as *partial*. Before, the last state was kept and the whole outage was counted as burn time
- Hours with more than 10 minutes of unknown burner state are left out of the comfort points, the heating curve and the "complete day" check behind the balance point and burn per degree-day
- No false short cycle when the entity comes back

### Fixed: comfort verdict no longer blames the curve when the boiler did not run
- Hours with the burner off and the rooms above the target (sun, people, cooking) are left out of the comfort gaps and of the trend
- "Offset too high" from overshoot in mild weather now needs the burner to have run at least 10 % of those hours
- `sensor.<name>_comfort_verdict` has two new attributes: `rule` (which rule decided) and `excluded_sunny_hours`

### New option: Sample flow target only while burning
- On by default. The flow target for the heating curve is read only while the burner fires, because some boilers report 0, the minimum or a frozen value while idle
- Targets below 10 °C are always ignored
- Turn it off (⋮ → **Configure**) if your boiler reports the real target when idle too and you want a curve point for every hour

### Upgrade
Update via HACS and restart Home Assistant. Stored statistics are kept. With the new option on, the heating-curve chart only gets points for hours in which the burner ran.
